# Поиск расписаний

Поиск работает без входа в БАРС, начиная с трёх символов после `trim()`.
[ScheduleClient](../src/API/ScheduleClient.ts) обращается к публичному источнику
`https://ts.mpei.ru`: `GET /api/search?term=...&type=...`, затем
`GET /api/schedule/<type>/<id>?start=YYYY.MM.DD&finish=YYYY.MM.DD&lng=1`.
Оба запроса используют выбранный `BARSBrowserProfile`, JSON Accept и Referer ts.mpei.ru,
с `credentials: omit`, без заголовков/токенов сессии БАРС.

## Выбор результата

[Парсер справочника](../src/API/Parsers/ScheduleDiscoveryParser.ts) проверяет весь
массив `{id, label, type}`, удаляет повторные ID. Название результата берётся из
`label`, а не из часто пустого поля `group` в занятии.

- Начальный тип: без цифр — `person`, с тремя цифрами подряд — `auditorium`,
  остальные запросы — `group`. Для сохранённых записей и переходов из занятия
  передаётся известный тип.
- Группы фильтруются и ранжируются до ограничения количества попыток. При вводе
  короче 7 символов скрыты группы с годом поступления более пяти лет назад.
  Точное название имеет приоритет, затем идут более молодые группы и записи
  без распознанного года. Год читается из конечного `-YY`.
- Если занятия первого кандидата пусты и ввод короче 5 символов, последовательно
  проверяются ещё два кандидата этого типа, затем до трёх кандидатов каждого
  оставшегося типа в порядке `group → auditorium → person`. При любой цифре
  `person` не запрашивается. Пустой справочник также разрешает этот переход.
- Выбор останавливается на первом расписании с занятиями. Если все найденные
  расписания пусты, сохраняется название первого кандидата и показывается отсутствие
  занятий. Если нет кандидатов — сообщение о том, что расписание не найдено.
- Сетевая ошибка, HTML/SSO, неверный JSON или повреждённая схема не считаются
  пустым расписанием и не разрешают молча выбрать другую группу.

За один поиск выполняются максимум 9 запросов занятий без цифр или 6 с цифрами,
плюс максимум один discovery на каждый тип. Лимит запроса вместе с чтением тела —
10 секунд; всего поиска — 30 секунд. Таймаут завершается и при fetch, который
игнорирует AbortSignal. Новый запрос, уход с экрана и смена сессии отменяют работу;
запоздалый результат не меняет интерфейс, историю или счётчик использований.
Одно успешное действие пользователя учитывается как один поиск, независимо от
числа проверенных кандидатов. Возврат на уже загруженный экран не запускает его снова.

Личное расписание использует тот же клиент, полный диапазон семестра и только
точное название группы студента. Подстановка произвольной группы при неудачном
разборе удалена; при сбое сохраняется возможность показать прежний офлайн-кеш.

## Разбор занятий и совместимость

[ScheduleParser](../src/API/Parsers/ScheduleParser.ts) сохраняет валидные даты,
сортирует дни/время, добавляет пустые промежуточные дни, удаляет точные дубликаты,
объединяет параллельные занятия и вставляет обед между занятиями. Nullable group,
stream, subGroup, listGroups и пустой listOfLecturers обрабатываются безопасно.
ФИО берётся из метаданных преподавателя; `lecturerOid` не подменяет person discovery ID.

Поле общего названия — `BARSSchedule.scheduleName`. При чтении прежнего кеша
`fullTeacherName` поддерживается как legacy alias без сброса аккаунта и расписания.
Формат снимка обоих виджетов не изменён: сериализатор не отправляет эти поля.

OSS оставлен отключённым: проверка 13.11.2026 нашла справочные записи, но не нашла
занятий в проверенных периодах 2024–2026. Возвращение источника требует подтверждения
актуальных непустых ответов, а не одного успешного HTTP-статуса.

## Последние и избранные

[ScheduleSearchLibrary](../src/Schedule/ScheduleSearchLibrary.ts) хранит по пять
записей в MMKV-контейнере `mpeiapp-schedule-search`, ключ `scheduleSearchLibrary`,
формат `version: 1`. В историю попадают найденные кандидаты с полным названием,
типом и ID, самые свежие первыми. Избранное не зависит от удаления из последних.
Это общие для устройства публичные расписания: доступны гостю и после входа,
сохраняются между запусками и при выходе из аккаунта.

В раскрытой панели слева — история, справа — избранное. Кнопки добавления скрываются
при заполнении пяти мест. Группы/аудитории отображаются полностью, ФИО сокращается
до фамилии и первой буквы имени только в интерфейсе. Повторный поиск передаёт
полное название и сохранённый тип через обычный поиск, с теми же лимитами/стоимостью.
