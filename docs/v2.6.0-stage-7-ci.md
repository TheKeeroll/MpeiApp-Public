## Когда запускаются проверки

Обычные push по-прежнему отслеживаются в `dev` и `v2`, pull request — в эти
же целевые ветки. Добавлен запуск при push любого тега. Используется
фактическая папка проекта `vpn-subscription-proxy`.

| Изменения без тега | Mobile quality | Metro smoke | Android debug APK | DragoNet proxy quality |
| --- | --- | --- | --- | --- |
| Только `.md` в любых папках и/или любое содержимое корневой `docs/` | Нет | Нет | Нет | Нет |
| Код приложения, iOS, tests, workflow, `yarn.lock`, patches | Да | Да | Нет | Нет |
| Корневой `package.json` | Да | Да | Да | Нет |
| Содержимое `android/`, кроме случая «только документация» | Да | Да | Да | Нет |
| Содержимое `vpn-subscription-proxy/`, кроме случая «только документация» | Да | Да | Нет | Да |
| Одновременно `android/`/корневой `package.json` и proxy | Да | Да | Да | Да |
| Push тега, в том числе на коммит только с документацией | Да | Да | Да | Да |

Правило документации имеет приоритет: например, изменение только
`android/README.md` или `vpn-subscription-proxy/README.md` не запускает
проверки. Учитываются также расширения `.MD` и `.Md`. Любые файлы внутри
`docs/`, включая изображения и JSON, относятся к документации.

Точный список Android-триггеров сохранён по заданию: отдельное изменение
`yarn.lock`, `ios/` или `patches/` не запускает APK. Для полного прогона такого
среза нужно отправить тег. Изменение `vpn-subscription-proxy/package.json`
запускает proxy, но не Android.

Тег должен быть отправлен в GitHub; локального `git tag` недостаточно.
Проверяемый коммит должен содержать обновлённый workflow. Для push тегов
GitHub не применяет `paths-ignore`, поэтому документация не отменяет полный
прогон. [Документация фильтров GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onpushpull_requestpull_request_targetpathspaths-ignore).

## Реализация

В [workflow](../.github/workflows/ci.yml) добавлены `paths-ignore` для `.md`
и `docs/**` на уровне событий. При обычном изменении только документации
workflow вообще не запускается: не выполняется даже служебная job.

Для остальных событий короткая job `Detect changed paths` выполняет checkout
с историей и запускает [Node-скрипт](../.github/scripts/ci-changes.cjs).
Она не устанавливает Yarn/npm-зависимости и выдаёт три булевых результата.
Четыре основные jobs зависят только от неё и затем выполняются независимо
друг от друга. Падение одной проверки не отменяет остальные.

Выбор jobs основан на Git diff:

- Push существующей ветки: весь диапазон `before..after`, включая несколько
  коммитов. Изменения кода не теряются, если последний коммит менял лишь README.
- Pull request: `base...head` от общего предка; изменения целевой ветки,
  не внесённые в PR, не включаются.
- Новая ветка с нулевым `before`: начальный снимок дерева, поскольку старого
  дерева для сравнения нет.
- Переименование учитывается как удаление и добавление: проверяются оба пути.
  Обычные удаления тоже учитываются. Имена разделяются NUL, поэтому пробелы
  и переводы строк в имени файла не меняют результат.
- Если SHA предыдущего среза отсутствует после force-push, скрипт пытается
  получить его из `origin`. При некорректном событии или недоступном коммите
  служебная job завершается с ошибкой; причина видна в её логе.
- Создание/обновление тега выбирает все проверки до разбора diff. Удаление
  ветки или тега не запускает проверки.

Двухточечное сравнение push и сравнение PR от общего предка соответствуют
[описанию GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#git-diff-comparisons).
Списки `added`/`modified`/`removed` из payload не используются: Actions не
предоставляет их для commit-объектов push.
[Событие push](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#push).

Разрешения workflow остаются `contents: read`. Доступ к production-секретам,
новые сторонние actions и зависимости для выбора jobs не добавлялись.
Существующие настройки Node 24, кэшей и срока хранения APK сохранены.

## Приёмка workflow после push

1. Изменить только `.md`/`docs/`: новый запуск CI не должен появиться.
2. Изменить только исходник приложения: служебная job, Mobile quality и
   Metro smoke выполняются; Android и proxy — skipped.
3. Изменить файл proxy: дополнительно выполняется DragoNet proxy quality.
4. Изменить `android/` или корневой `package.json`: выполняется Android debug APK.
5. Отправить тег на срез с этим workflow, включая документационный коммит:
   выполняются все четыре основные jobs.

Для публичного репозитория стандартные GitHub-hosted runners не тарифицируют
время выполнения jobs. Хранение артефактов/кэша учитывается отдельно; новые
фильтры сокращают ненужную работу и создание APK-артефактов.
[Условия GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions).
