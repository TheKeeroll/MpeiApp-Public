# Этап 13: проверка обновлений магазинов

**Завершён в релизе 2.6.0 от 11.11.2026.** Новая сборка с этапами 12–13
успешно прошла Xcode Cloud, внешнее тестирование и публикацию в магазинах.
Общая iOS-приёмка подтверждена тестировщицей. [Итоги релиза](v2.6.0-release.md).

## Когда выполняется проверка

`AppUpdateCheck` подключён рядом с основным экраном в App.tsx, внутри AdsProvider
и Redux/Paper providers. Проверка ждёт состояния входа `NOT_LOGGED_IN` /
`STUDENTS_NOT_FOUND` либо `LOGGED_IN` с завершённой загрузкой оценок:
`LOADED`, `OFFLINE` или `FAILED`. Ошибка основной загрузки не скрывает возможность
предложить обновление, которое может её исправлять.

После готовности интерфейса пропускаются два animation frame: запрос магазина
не входит в цепочку авторизации или загрузки учебных данных. В рамках одного
открытия проверка выполняется один раз, независимо от повторных render,
перехода из входа в БАРС или обновления оценок. При background запрос отменяется,
его поздние результаты игнорируются; после foreground запускается новый цикл.
Краткий `inactive → active` при системном разрешении не считается новым открытием.

Найденное обновление ждёт закрытия окна рекламных согласий; добавлена пауза
500 мс для завершения native dismissal в iOS. При авторизации/загрузочном экране
или неактивном приложении окно обновления не показывается. «Позже» закрывает его
до следующего открытия приложения, без постоянного подавления будущих проверок.

## Запросы и ограничения времени

`APP_STORE_PAGES` в Constants содержит ровно заданные платформенные URL:

- [Google Play](https://play.google.com/store/apps/details?id=com.mpeiapp)
- [App Store](https://apps.apple.com/ru/app/mpeiapp/id1618910681)

По этой же строке `storeUrl` выполняется `Linking.openURL`: система может открыть
соответствующий магазин. Ссылка не заменяется другим endpoint или URI-схемой.

`BARSAPI.GetBARSBrowserProfile()` возвращает копию выбранной идентичности
браузера. `CreateAppStoreHeaders` добавляет User-Agent/client hints и русский
Accept-Language, без origin/referer/auth headers БАРС. Используется публичный
`fetch` с `credentials: 'omit'`, а не `FetchUniversity`, который обрабатывает
состояние университетской сессии. Ошибка магазина не меняет профиль БАРС.

Каждая попытка ограничена **10 секундами**, включая `response.text()`.
Таймаут реализован через Promise.race и AbortController, чтобы завершиться
даже при игнорировании abort нативным fetch. HTTP-ошибка, сетевой отказ,
ошибка чтения и нераспознанная страница дают до двух повторов: через **1 секунду**
после первого провала и через **3 секунды** после второго. Всего три попытки,
максимум примерно 34 секунды сетевого ожидания в фоне. После третьего провала
результат тихо считается отсутствием найденного обновления. Успешный ответ
с равной/меньшей версией завершает проверку сразу, без повторов.

## Парсинг и сравнение

`src/API/Parsers/AppStoreParser.ts` работает без выполнения кода страницы:

| Магазин | Основной источник | Резервная разметка |
| --- | --- | --- |
| Google Play | JSON `data` из AF_initDataCallback для MpeiApp; текущие поля `141` (версия) и `145` (изменения) | Прежние массивы `[140]`/`[144]`, semantic itemprop version/releaseNotes |
| App Store | `serialized-server-data`, нужный app ID и `shelfMapping.mostRecentVersion.items[0]` | Локальная секция whats-new, её version и полный content |

JSON Google извлекается сканированием сбалансированных скобок с учётом строк
и escape; `eval` / Function не используются. Версия не угадывается по отзыву,
описанию приложения, системным требованиям или старым записям истории.

HTML изменений преобразуется в текст с сохранением переносов, абзацев и
маркеров, HTML entities декодируются. Если текст содержит несколько версий,
выбирается заголовок актуальной версии и содержимое до следующего заголовка
другого релиза. Обычное упоминание старой версии внутри пункта не режет текст.
Искусственного лимита длины списка нет. Отсутствующий номер/непонятная структура
считаются ошибкой парсинга; пустой корректный текст изменений допускается
и получает нейтральную подпись в окне.

`AppVersion.ts` удаляет v/«Версия»/Version и суффиксы канала/build, оставляя
числовые компоненты: `v2.6.1-preview` → `2.6.1`. Сравнение числовое:
2.10.0 > 2.9.9, 2.6 = 2.6.0, 2.6.0-preview = 2.6.0. Обновление предлагается
только при строго большей версии магазина.

09.11 парсер проверен на **полных свежих HTML-ответах** обеих официальных страниц:
извлечены версии 2.5.0 и полные изменения последнего релиза. У Google Play блок
2.4.0 успешно отрезан. Для текущего приложения 2.6.0 такой ответ не вызывает окно.
В `__tests__/fixtures/store-pages` сохранены сокращённые реальные структуры
только с релизными полями, без отзывов, пользователей и служебных токенов.

## Окно и проверка

`AppUpdateModal` использует размеры, safe area, шапку и закреплённые кнопки
по образцу окна согласий. Заголовок — «Доступна новая версия», номер крупный
и жирный, затем весь список изменений. Заданный пользователем текст
предупреждения выводится целиком цветом `warning`. «Позже» слева,
«Обновить через Google Play/App Store» справа. Анимированная кнопка выделена
в общий `AnimatedActionButton`, поэтому оба окна используют один визуал
и одинаково соблюдают Reduce Motion / остановку анимации в фоне.
Ошибка открытия магазина показана в окне и позволяет повторить попытку;
«Позже» и Android Back остаются доступными.

Автоматические проверки покрывают парсинг реальных структур и резервной
разметки, длинные изменения, нормализацию версий, обе платформы, выбранный
browser profile, точные интервалы повторов, отсутствие зависания fetch/body,
отмену, поздние результаты, загрузку основных экранов, возврат из фона,
очередь после согласий и поведение кнопок. Успешны `yarn typecheck` и полный
`yarn test:ci`: **48 suites / 532 tests**, из них **58 новых проверок** этапа 13.
Регрессии окна рекламных согласий после выделения общей кнопки также успешны.
Проверены наличие выбранных иконок в установленных шрифтах и `git diff --check`.

Регрессионная матрица для Android и iPhone:

| Сценарий | Ожидаемый результат |
| --- | --- |
| Холодный запуск с входом/без входа/offline | Основной экран появляется прежде проверки; равная/старая версия не вызывает окно |
| Новая версия, в том числе номер с v/preview | Нормализованный номер, только нужный релиз и полный текст |
| Новое окно рекламных согласий | Обновление ждёт закрытия согласий |
| «Позже», навигация и перезагрузка оценок | Повторного окна в текущем открытии нет |
| Возврат из background | Один новый цикл проверки |
| Плохой интернет/HTTP error/неизвестная разметка | Работа приложения продолжается; максимум три попытки |
| «Обновить через…» | Исходный URL открывает страницу MpeiApp в магазине/доступном обработчике |
| Длинный текст, узкий экран, крупный шрифт, темы | Текст прокручивается, нижние кнопки доступны |
| Reduce Motion и фон | Блик останавливается |

Внешние магазины могут менять HTML независимо от MpeiApp: неизвестный формат
приводит к тихому пропуску проверки после заданных повторов.
