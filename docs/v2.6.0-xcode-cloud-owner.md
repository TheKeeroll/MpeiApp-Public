# MpeiApp: сопровождение доступа и подписи Xcode Cloud

Первичное подключение выполнено. Cloud Build/Archive/export, внешнее TestFlight
и публикация 2.6.0 от 11.11.2026 подтверждены пользователем. Инструкция сохранена
для восстановления рабочего окружения и сопровождения аккаунта, а не как
список незавершённых действий релиза. [Итоги](v2.6.0-release.md).

## Роли

Account Holder управляет членством, соглашениями Apple, Identifiers/Profiles
и App Groups текущей Team. Роль Admin в App Store Connect сама по себе
не даёт доступа к Developer Program ресурсам индивидуального аккаунта
и не гарантирует появления Team в локальном Xcode.

Admin сопровождает доступные workflow, сборки, TestFlight и Cloud variables
в браузере. GitHub App подключает пользователь с правами владельца/администратора
репозитория; это отдельное разрешение от роли Apple. Первое подключение
к существующей MpeiApp выполнено владельцем на Mac.

## Локальный Mac

Проверенный локальный Xcode — 26.4 (17E192). Выбранный Xcode проверяется
`xcodebuild -version`; Cloud независимо использует свой workflow image.
Для уже клонированного репозитория сначала сохраняются собственные изменения,
затем обновляется нужная ветка. Открывается **ios/MpeiApp.xcworkspace**,
а не отдельный xcodeproj.

Локальные `src/config/Secrets.ts` и `ios/MpeiApp/YandexMapsInitializer.swift`
передаются прежним закрытым каналом и не добавляются в Git. Установка по
зафиксированным lockfiles описана в [Cloud README](../ios/ci_scripts/README.md#проверенные-lockfiles-и-установка-на-mac).
Повторный resolver, bundle update и удаление lockfiles для обычной установки не нужны.

Группа должна быть назначена обоим App ID в Developer Account и совпадать
с entitlements и ScheduleWidgetContract. Виджет не требует отдельного приложения
в App Store Connect. Изменения signing/capabilities сохраняются в репозитории
до Cloud-запуска: локальные несохранённые настройки Xcode в него не попадут.
Старые занятые ID прежней Team не возвращаются.

## Workflow и передача сопровождения

Работа ведётся в **одном существующем продукте MpeiApp**. Первый workflow
создаётся через Xcode Report navigator → Cloud → Get Started только при
восстановлении подключения; для обычного изменения кода onboarding не повторяется.
Используются release-* и testflight-* теги; source diagnostics не блокирует
другие события, разрешённые workflow. Точная матрица — в
[настройках Cloud](../ios/ci_scripts/README.md#настройки-распространения-и-запуска).

Archive — **TestFlight and App Store**, с Clean и Restrict Editing.
Shared variables помечаются Secret; Only the Account Holder не включается
для тех значений, которые должен сопровождать Admin. Общий build counter
устанавливается выше уже занятых номеров и не сбрасывается между ветками.

При проблемах доступа сверяются Apple Account, текущая Team, роли, доступ
к существующему продукту/workflow и назначение shared variables. Ошибки
доступа Apple не исправляются изменением Git-тегов или пересозданием приложения.
Действие и его Logs доступны в App Store Connect → MpeiApp → Xcode Cloud → Builds.

Полный список имён конфигурации: `node scripts/xcode-cloud.cjs variables`.
Значения и исходные секретные файлы в issue, logs и публичный Git не передаются.
[Конфигурация](../ios/ci_scripts/README.md#cloud-secret-variables).
