# MpeiApp: первоначальная настройка Xcode Cloud владельцем аккаунта

Подготовлено **23.10.2026** для Account Holder, на чей аккаунт перенесено MpeiApp.
Admin уже обновил зависимости, собрал и запустил приложение в Simulator с
**Xcode 26.4 (17E192)**; lockfiles сохранены в коммите `049ad61`.
Нужная Team недоступна Admin, поэтому первое подключение выполняет владелец.
После него workflow и TestFlight сможет сопровождать Admin через браузер.

## 1. Установить Xcode 26.4 (17E192)

Для этой версии нужна **macOS Tahoe 26.2 или новее**. Скачать именно Xcode 26.4
через [Apple Downloads](https://developer.apple.com/download/all/?q=Xcode%2026.4),
распаковать `.xip` и поместить приложение, например, в
`/Applications/Xcode-26.4.app`. Выбрать вариант для архитектуры своего Mac.
Открыть Xcode один раз и завершить установку предлагаемых компонентов.
Требование macOS указано в [release notes Apple](https://developer.apple.com/documentation/xcode-release-notes/xcode-26_4-release-notes).

В Terminal выбрать этот Xcode; если он установлен по другому пути, изменить
первую команду:

```bash
sudo xcode-select --switch /Applications/Xcode-26.4.app/Contents/Developer
sudo xcodebuild -license accept
sudo xcodebuild -runFirstLaunch
xcodebuild -version
```

Ожидается `Xcode 26.4` и `Build version 17E192`.

## 2. Получить актуальную ветку dev

Для нового рабочего каталога:

```bash
git clone --branch dev https://github.com/TheKeeroll/MpeiApp-Public.git
cd MpeiApp-Public
git log -1 --oneline
```

Если проект уже склонирован, перейти в его каталог и выполнить
`git status --short`. Сначала сохранить свои незакоммиченные изменения, если
они есть. Затем вместо клонирования:

```bash
git fetch origin --prune
git switch dev
git pull --ff-only origin dev
git log -1 --oneline
```

Каталог должен содержать коммит `049ad61` или его потомка. Полученные от
DragonSavA закрытым каналом файлы разместить в `src/config/Secrets.ts` и
`ios/MpeiApp/YandexMapsInitializer.swift`; в Git они не добавляются.

## 3. Установить зависимости и открыть workspace

Если Homebrew ещё нет, установить его по [brew.sh](https://brew.sh/) и выполнить
выведенные установщиком Next steps, включая добавление `brew` в PATH.
Далее из корня репозитория, в одной сессии Terminal:

```bash
brew install node@24 ruby@3.3
export PATH="$(brew --prefix node@24)/bin:$(brew --prefix ruby@3.3)/bin:$PATH"
gem install bundler --version 2.4.10 --user-install --no-document
export PATH="$(ruby -e 'print Gem.user_dir')/bin:$PATH"
npm install --global --prefix "$HOME/.mpeiapp-local/node" yarn@1.22.22
export PATH="$HOME/.mpeiapp-local/node/bin:$PATH"

export BUNDLE_FROZEN=true BUNDLE_PATH="$HOME/.mpeiapp-local/bundle"
bundle _2.4.10_ install
yarn install --frozen-lockfile --non-interactive --production=false
cd ios
bundle _2.4.10_ exec pod install --deployment
cd ..
node scripts/xcode-cloud.cjs preflight

node --version
yarn --version
ruby --version
bundle _2.4.10_ exec pod --version
bundle _2.4.10_ exec ruby -rxcodeproj -e 'puts Xcodeproj::VERSION'
git diff --stat
open ios/MpeiApp.xcworkspace
```

Ожидаются Node 24.x, Yarn 1.22.22, Ruby 3.3.x, CocoaPods 1.17.0 и xcodeproj
1.28.1; preflight сообщает `CocoaPods lockfiles ready`. Lockfiles уже проверены:
`bundle update`, `pod update` и удаление lockfiles для этой установки не нужны.
Локальный Archive перед Cloud не требуется; Simulator уже проверен Admin.

## 4. Проверить проект и текущую Team

В **Xcode → Settings → Accounts** войти Apple Account владельца с активным
членством Developer Program. При необходимости принять обязательные соглашения
Apple в браузере. В открытом workspace проверить:

| Параметр | Значение |
| --- | --- |
| Scheme | `MpeiApp`, флаг Shared в Manage Schemes |
| Edit Scheme → Archive | Release; приложение включено в Build → Archive |
| Team приложения и ScheduleWidgetExtension | Текущая Team получателя, которой выпускались последние версии; не Personal Team |
| Signing обеих целей | Automatically manage signing; без ошибок provisioning |
| Bundle ID приложения | `ru.NoobDragons.MpeiApp` |
| Bundle ID виджета | `ru.NoobDragons.MpeiApp.ScheduleWidget` |
| App Groups обеих целей | `group.com.mpeiapp`, доступная текущей Team |
| Version / minimum iOS | 2.6.0 у приложения и виджета; minimum 15.6 / 17.0 соответственно |

Сверить также остальные существующие capabilities приложения с правами Team.
Если потребуется изменить signing/capabilities в файлах проекта, передать diff
DragonSavA для сохранения и push **до облачной сборки**: Cloud берёт код с GitHub,
а не несохранённые настройки локального Xcode.

## 5. Подключить первый workflow

В **Report navigator → Cloud → Get Started** выбрать существующую **MpeiApp**
в текущем аккаунте. Новое приложение/другой bundle ID создавать не нужно.
В **Edit Workflow**, до первого Start Build, установить:

| Настройка | Значение |
| --- | --- |
| Имя | `MpeiApp dev TestFlight` |
| Environment | Xcode 26.4, если доступен; точную версию образа записать |
| Start condition | Tag Changes, префикс `ios-dev-`; убрать предложенные Branch/PR conditions |
| Actions | Только один iOS Archive, scheme MpeiApp, Release |
| Deployment Preparation | **TestFlight and App Store** — сборка должна подходить для релиза |
| General | Включить Restrict Editing и Clean |
| Post-action | TestFlight, согласованная внутренняя группа тестировщиков |

Наличие Xcode 26.4 на Mac не гарантирует его наличие в Cloud. Если его нет
в списке образов, согласовать с DragonSavA доступный стабильный Xcode 26+;
версию Cloud выбрать явно. Локально использовать проверенный 26.4 (17E192).

В Environment ввести **14 обязательных Secret variables** из переданного
Secrets.ts; точные имена и соответствие полям приведены в
[таблице конфигурации](../ios/ci_scripts/README.md#cloud-secret-variables).
Если порты или subscription path отличаются от defaults, задать их явно.
Список имён без значений также выводит `node scripts/xcode-cloud.cjs variables`.
GitHub Repository secrets здесь не используются. Для дальнейшего сопровождения
Admin не включать **Only the Account Holder** у shared variables; после создания
второго workflow Admin сможет применить общую конфигурацию к обоим.

В **Grant Access** связать свой Apple Account с GitHub. Установить Xcode Cloud
GitHub App только для `TheKeeroll/MpeiApp-Public`; если прав GitHub недостаточно,
передать запрос владельцу/администратору репозитория и сообщить DragonSavA.
После подтверждения вернуться в мастер и завершить подключение.

## 6. Запустить первую сборку и передать сопровождение Admin

**До первого Start Build** сверить с Admin уже занятые build numbers версии
2.6.0. Если нужно, после создания workflow открыть **App Store Connect →
MpeiApp → Xcode Cloud → Settings → Build Number** и поставить Next Build Number
выше занятого максимума. Счётчик общий для dev и v2 в одном продукте MpeiApp;
скрипты применяют CI_BUILD_NUMBER и к приложению, и к виджету.

В мастере выбрать **dev** и выполнить один первоначальный ручной Start Build:
скрипты допускают такой запуск без тега. Дальнейшие автоматические dev-сборки
запускаются опубликованным тегом `ios-dev-*` на коммите из dev. Workflow v2
для каждого push и общие переменные затем настроит Admin; оба workflow должны
оставаться **TestFlight and App Store**. Принятый тестерами dev-build можно
выпустить без повторной сборки из v2.

Проверить результат: **App Store Connect → MpeiApp → Xcode Cloud → Builds →
сборка → действие → Logs**; после успешной обработки — та же 2.6.0 (номер)
в TestFlight. Если сборка упала, передать Admin ссылку и лог упавшего действия.
Проверить, что Admin видит Cloud и может редактировать workflow. Оставить
включённые **25 compute hours/месяц**, платный тариф не подключать.

Передать DragonSavA ссылку на запуск, commit SHA, точные локальную/Cloud версии
Xcode, результат и номер сборки. Последующая настройка и приёмка описаны в
[этапе 11](v2.6.0-stage-11-xcode-cloud.md#c-пользователь-app-store-connect-в-браузере).
