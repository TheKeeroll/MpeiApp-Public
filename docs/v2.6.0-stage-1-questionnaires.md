# v2.6.0: обязательные анкеты и экспериментальное автозаполнение

Этап 1 реализует обнаружение ограничения БАРС, отдельный экран,
ручное восстановление и добровольное автоматическое заполнение.
Код проверяется по обезличенным HTML и моделируемым ответам;
при разработке анкеты реального студента не отправлялись.

## Обнаружение и сохранение сессии

[ParseMandatoryQuestionnaires](../src/API/Parsers/MandatoryQuestionnairesParser.ts)
распознаёт banner `divAlert` и обязательные незавершённые строки таблицы,
включая partial HTML. Обычные, завершённые и просроченные анкеты,
красные значки вне нужной таблицы и HTML внутри обычного JSON не блокируют
приложение. Форма login/2FA имеет приоритет над оформлением страницы анкет.
Названия сохраняются даже при неполных колонках/отсутствующих ID;
для автоматической отправки нужны корректные идентификаторы.

`BARS.FetchUniversity` читает ответы университетских HTTP-запросов до
предметных парсеров и JSON-разбора. Используется в восстановлении сессии,
multi-account, оценках/долгах, зачётке по семестрам, пропусках, заданиях,
отчётах, книгах, анкетах, стипендиях, приказах, расписаниях, GET почты
после входа и проверке согласия на оценку прямо из UI.

Auth/2FA/QR и внешние сервисы исключены. У BARS_MAIN назначение уточняется
вызывающим кодом: получение формы входа остаётся auth, повторная проверка
кабинета — данные. Дополнительно HandleLoginResponse распознаёт анкету
в уже полученном успешном HTML кабинета после password/2FA, без изменения
обработки ошибок кода/пароля.

Ограничение даёт `QUESTIONNAIRES_REQUIRED`, сохраняет credentials,
browser profile, cookies native fetch и принятый временный 2FA-код.
Генерация сессии защищает от поздних ответов предыдущего аккаунта;
дополнительная проверка ограничения защищает кеш от параллельных ответов
той же сессии. Core finally и фоновая очередь не возвращают LOGGED_IN
поверх этого состояния. Перенаправленный HTML не становится пустыми
успешными учебными данными и не запускает cache fallback.

## Экран и настройка

[MandatoryQuestionnairesScreen](../src/Screens/Login/MandatoryQuestionnairesScreen.tsx)
показывает причину, названия/описания и неполноту списка. Доступны переход
на сайт, экспериментальное заполнение, повторная проверка и logout.
Есть прокрутка и переносы длинных текстов без фиксированной высоты карточек.
Заголовок имеет отступ под плавающий счётчик лояльности с учётом масштаба
системного шрифта. Описания свёрнуты по умолчанию; нажатие на название
раскрывает описание отдельной анкеты. При смене сессии раскрытия сбрасываются.
Все кнопки используют общий [AuthButton](../src/Login/AuthButton.tsx)
с тем же оформлением, что на экранах входа и второго фактора.

В начале «Прочее» появился подраздел «Настройки» с тем же
[AutomaticQuestionnairesSwitch](../src/Questionnaires/AutomaticQuestionnairesSwitch.tsx),
который показан на специальном экране. Его значение хранится в MMKV
как общая настройка приложения, по умолчанию false. Alert включения
поясняет нейтральные/случайные ответы и отсутствие дальнейших подтверждений.
Отмена оставляет false; выключение прекращает текущий автоматический запуск.
Кнопка и switch имеют бейдж «Экспериментально» с иконкой AntDesign `experiment`.
В установленном `react-native-vector-icons@10.3.0` этого glyph нет;
используется локальный PNG 96×96 с прозрачностью и цветом текущей темы.
Рядом сохранены [официальный SVG](../assets/images/Questionnaires/experiment.svg)
из [AntDesign Icons](https://github.com/ant-design/ant-design-icons/blob/master/packages/icons-svg/svg/outlined/experiment.svg)
и [MIT-лицензия](../assets/images/Questionnaires/AntDesign-LICENSE.txt).
Новой нативной зависимости для иконки не добавлено.

Ручной запуск также требует подтверждения. Подтверждение, оставшееся от
прежней сессии, не начинает работу в новом аккаунте. Во время заполнения
показываются анкета/число сохранённых ответов; кнопка меняется на остановку.
Повторная проверка блокируется, пока работает другая операция.

## Получение полного списка

Список запрашивается по логину без student.id, с попыткой PageSize=500.
При фактической пагинации используются `data-q-href` и JSON в параметре
`query`; Page/PageSize/SortOrder берутся из ответа. ID строк обеспечивают
дедупликацию, включая одинаковые названия разных анкет. Предел — 20 страниц
и 2000 записей. При ошибке остаются уже полученные названия и предупреждение
о неполноте; автоматическое заполнение неполного списка не начинается.

Повторная проверка начинает с защищённого GET с текущими cookies.
Снятое ограничение приводит к новой генерации загрузки данных, сохраняя
авторизованную сессию и profile; пароль повторно не отправляется.
Сетевая ошибка оставляет экран анкет. Реальная форма входа означает
истечение сессии и возвращает в существующий login/2FA flow.

## Отправка ответов

[Парсер вопроса](../src/API/Parsers/QuestionnaireQuestionParser.ts) и
[последовательный исполнитель](../src/Questionnaires/QuestionnaireAutoFill.ts)
работают по предоставленным `getAnswer`/`editQuestion`:

1. GET EditQuestionFirst с `uslkID`/`qqaID` из обязательной строки.
2. Выбор нейтральных вариантов по порядку «Затрудняюсь ответить», «не знаю»,
   «не знал(а)», «Нет», затем случайный допустимый вариант. Среди вариантов
   одинакового приоритета выбор случайный. «Нет» — отдельное слово.
3. Textarea получает одну из трёх заглушек: `-`, три пробела,
   «Затрудняюсь ответить». Поддержаны обычный выбор, вариант с текстом,
   select, шкала и составные поля с разделителями `|p|`/`|a|`.
   При пустом select сотрудника используются варианты его штатного JSON API.
4. Multipart POST `mode=1`, `answer`, при наличии — verification token.
   Content-Type/boundary и Content-Length multipart создаёт native fetch.
   В запросах сохраняются cookie jar и выбранные desktop headers;
   JSON-ответ требует `success=true`.
5. Следующий GET берётся из `result.url`, разрешённого относительно текущего
   вопроса. Арифметики qID нет. Адрес ограничен BARS origin, известными
   страницами вопроса/подтверждения и теми же `uslkID`/`qqaID`.
6. Уже отмеченные как сохранённые ответы не перезаписываются.
7. На странице завершения отправляется form-urlencoded POST
   SubmitQuestionnaireAnswer с обоими ID; успешность подтверждается
   свежим списком и затем доступом к кабинету.

Неподдерживаемые поля (включая файлы), неверные ID/адрес, повтор вопроса,
непринятый ответ и неподтверждённое завершение останавливают обработку.
Предел — 50 анкет за проход, 200 переходов в одной анкете, до трёх
последовательных проходов по оставшимся обязательным анкетам в одном запуске.
Автоматические ошибки не создают повторяющихся запросов;
следующая попытка требует действия пользователя/нового ограничения.
Logout, новый аккаунт и остановка отменяют дальнейшие операции. Уже
отправленные ответы сервер сохраняет, приложение их не откатывает.

## Зависимость и проверки

Добавлен только JS-пакет `react-native-url-polyfill@4.0.0`, импортируемый
локально как URL/URLSearchParams. Встроенный RN URL иначе разрешает
некоторые относительные адреса. Это
[поддерживаемый вариант использования пакета](https://github.com/charpeni/react-native-url-polyfill#option-3-convenient--ponyfill);
глобальные реализации и нативные pods/Gradle не заменяются.
Jest разрешает преобразование его ES modules; существующие patch-package
исправления повторно применены после установки JS-зависимости.

Автоматические проверки покрывают parser fixtures, приоритет auth,
пагинацию/частичную ошибку, сохранение кеша/profile/временного 2FA,
реальное JS-представление RN FormData, все изученные поля, серверные URL,
подтверждение завершения, остановку, отсутствие автоповторов и UI switch.
Исходные регрессионные тесты также сохраняются.

Итоговые проверки 12.10.2026 после корректировок UI и этапа 2:
`yarn typecheck` успешен; `yarn test:ci` — **23 suites / 150 tests прошли**.
Fixtures проверены
на отсутствие исходных UUID/имён, документы — на локальные ссылки и whitespace.

## Проверка пользователем и оставшаяся приёмка

Пользователь проверил на эмуляторе с реальным затронутым аккаунтом
распознавание блокировки, экран с пояснением и переход на сайт для ручного
заполнения — эти части работают. Автозаполнение проверить не удалось:
сначала БАРС стал недоступен, а после восстановления сайта анкета уже
получила обычный статус и вход завершился без ограничения. Реальная
автоматическая отправка и завершение анкеты остаются непроверенными.
Экспериментальный исполнитель, кнопка и настройка сохраняются на случай
появления новых обязательных анкет.

Для продолжения ручной проверки на реальном устройстве в этапе 6:

- Первый вход, 2FA и restore с обязательной анкетой: специальный экран,
  credentials/cookies/profile сохраняются; необязательные анкеты не блокируют.
- Заполнение на сайте и «Проверить снова»: кабинет восстанавливается
  без password POST, а истёкшая сессия проходит обычный вход.
- Ручной экспериментальный запуск с подтверждением: простые и составные
  вопросы, server result.url, окончательное подтверждение и статус анкеты.
- Включение/отмена/перезапуск приложения: настройка одна на двух экранах;
  при включённом режиме новые ограничения не требуют Alert для заполнения.
- Offline, неизвестная форма, остановка, выключение и logout во время
  запроса: нет новых POST после отмены и нет автоматического цикла ошибок.
- Обе темы, Android/iOS, крупный шрифт, длинные названия и малый экран.

Сборки, реальные ответы БАРС, commit и push на этапе разработки не выполнялись.
