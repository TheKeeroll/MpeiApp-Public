# Практическая ценность каждого релиза

Каждый релиз MpeiApp должен содержать хотя бы одну практическую ценность для
студентов **на каждой платформе: Android и iOS**. Польза может быть общей для
обеих платформ или разной, но её нужно обосновать и проверить отдельно для каждой.
Правило применяется и к срочным обновлениям.

Практическая ценность — наблюдаемое улучшение студенческого сценария: восстановление
доступа к БАРС, исправление поиска расписания, повышение удобства виджета,
устранение сбоя или иной проблемы, мешающей пользоваться приложением.

Обновление рекламного SDK, адаптеров, инструментов сборки или внутренний рефакторинг
сами по себе этого требования не выполняют. Они могут сопровождать полезные изменения.
Исправление, затрагивающее только iOS, подтверждает пользу для iOS; для Android
в составе того же релиза также требуется практическое улучшение, и наоборот.

При планировании релиза в локальном плане заполняется короткая таблица:

| Платформа | Практическая ценность для студентов | Сценарий проверки и результат |
| --- | --- | --- |
| Android | Конкретное изменение поведения | Как воспроизвести и подтвердить пользу |
| iOS | Конкретное изменение поведения | Как воспроизвести и подтвердить пользу |

Перед финальным Gate обе строки должны иметь подтверждённый результат на
соответствующей платформе. Успешная сборка или одобрение магазина не заменяют
проверку пользовательского сценария. В описании обновления каждого магазина
следует назвать практические изменения, доступные его пользователям.

Будущие планы и матрицы приёмки хранятся локально в исключённых из Git каталогах
`docs/update_plans/` и `docs/roadmap/`. Публичная документация фиксирует общее правило
и фактически выпущенное поведение.
