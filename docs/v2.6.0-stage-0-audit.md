| `data-q-page` / `data-q-page-size` | Текущая страница и размер; значения берутся из ответа, а не угадываются по URL |

Скрипт `getQuery__PartialListQuestionnaireAnswer()` формирует JSON:

```json
{
  "ID": null,
  "State": null,
  "SortOrder": "QuestionnaireAnswerStatu.SortOrder,EditEndDate desc,Questionnaire.Name",
  "Page": "1",
  "PageSize": "10",
  "SearchText": ""
}
```

`ID`/`State` — значения одноимённых атрибутов таблицы; в исходнике атрибуты
отсутствуют и `getAttribute` возвращает null. При `State == 1` дополнительные
поля не добавляются. Поиск предварительно нормализуется через `ENtoRU`.
Сохранённый `loadTableByQueryAsyncV2` подтверждает **GET** по `data-q-href`
с параметром `query`, равным JSON-строке. Ссылка pager `/2` служит источником
номера страницы: JS записывает номер в `data-q-page` и выполняет partial GET.
Переключение PageSize возвращает страницу на 1.

Для этапа 1: URL resolving через текущий BARS origin, один `encodeURIComponent`
для значения `query`, текущие cookies/headers, проверка session generation
после ожиданий. Не переносить реальные ID в код; не выдавать cookies БАРС
произвольному хосту из HTML. Увеличение PageSize до 500 остаётся попыткой:
полнота подтверждается pager/полученными строками. Обход должен иметь предел
страниц и проверку уже посещённых страниц/ID; частичная ошибка сохраняет
факт блокировки и доступные названия, не запускает повторный вход.

Вторая страница fixtures синтетическая. Реальный полный перечень обязательных
анкет и точные маршруты серверных redirect из одного HTML установить нельзя.
Это не ограничивает выбранный общий охват проверки ответов.

## Охват перехвата ответов

Требование разработчика от 12.10.2026: потенциально затронут **любой запрос
к сервисам вуза**, кроме непосредственно входа, 2FA и QR. Точно подтверждены
список студентов / multi-account и основные разделы кабинета. Перехват
не строится на закрытом списке этих маршрутов.

В этапе 1 нужен общий путь чтения университетских ответов, доступный и из
`BARSAPI`, и из UI. Назначение запроса передаётся явно: по умолчанию данные
вуза; отдельные исключения — auth, 2FA, QR. Принадлежность университету
определяется по разобранному hostname (`mpei.ru` и его поддомены), а не
совпадению подстроки. Новые запросы учебных данных используют тот же путь.
Глобальную замену `fetch` не вводить.

Ответ читается один раз до предметных парсеров, `JSON.parse`, успешных
Redux-обновлений и MMKV-записей. Для JSON API проверяется возможность
неожиданного HTML вместо JSON; обычный JSON не передаётся HTML-парсеру.
Нельзя полагаться только на Content-Type, HTTP 200 или `response.url`:
native fetch может уже пройти redirect, а сервер — вернуть partial HTML.
Форма login/2FA вместо данных обрабатывается существующим auth flow;
banner/обязательные незавершённые строки дают `QUESTIONNAIRES_REQUIRED`.
Отсутствие блокировки не отменяет валидацию ожидаемой страницы.

| Источник | Запросы для общего перехвата |

| `FetchCachedDataSection` и его request callbacks | Пропуски, отчёты, задания, книги, анкеты, стипендии, приказы; проверка до parser/cache fallback |
| `FetchCurrentWeek` | HTML расписания на `mpei.ru` |

пока объявлены только в Constants, активных вызовов не найдено. При появлении
их реализации применяется то же правило; не смешивать их с уже используемым
`BARS_MULTI_ACCOUNT`.

### Исключения

- GET BARS_MAIN для получения login token, password POST, auth-продолжение
  `?sod=1`; BARS_MAIN может использоваться и для данных, поэтому один URL
  не является основанием исключать все его запросы.
- Запрос кода `JSON_SendAF2_Code`, POST `LoginCode` и другие операции 2FA.
- QR-регистрация из `QRCodeScanner.tsx`, включая URL с `ReturnUrl` на QR
  и связанные переходы. Не менять этот поток общим перехватом.
- Непосредственная авторизация университетской почты.
- DragoNet proxy, Firebase, рекламные SDK, карты, NetInfo и остальные
  операции вне университетских HTTP-данных. Открытие внешнего браузера
  через Linking не является чтением ответа внутри приложения.

После успешного password/2FA запускаются защищённые GET и их проверка.
Auth handlers должны передать обнаруженное при этих GET ограничение как
успешную аутентификацию с недоступным кабинетом, сохранив принятый код,
credentials, cookies и browser profile. Auth POST не добавляется в общий
перехват университетских данных.

### Требования к распространению результата

1. Ограничение связано с текущими аккаунтом и session generation;
   публикуется один раз для активной загрузки. Поздний ответ после logout
   или смены аккаунта игнорируется.
2. Специальный outcome проходит через `FetchCachedDataSection`,
   `RunDataSection`, auth/restore catch и UI catch. Его нельзя превратить
   в OFFLINE, STUDENTS_NOT_FOUND, пустые оценки или ошибку автозачёта.
3. Остановить новые защищённые запросы фоновой очереди; ответы уже начатых
   запросов после обнаружения блокировки не перезаписывают состояние
   и кеш. Одной проверки generation недостаточно для параллельных ответов
   внутри той же ограниченной сессии.
4. `LoadOnlineDataInternal` сейчас устанавливает LOGGED_IN в finally;
   этот и остальные завершающие переходы должны учитывать ограничение.
   Нужны проверки как после core Promise.allSettled, так и в фоне/retry.
5. Перечень получает логин из credentials; `student.id` может ещё не быть.
   Повторная проверка начинает с защищённого GET, а не password POST.

VK 5.51.2.2, Liftoff 7.7.8.1 и Chartboost 9.14.0.1. Их POM требуют

[Список Яндекса](https://ads.yandex.com/helpcenter/ru/dev/react-native/list-network)
указывает у пяти сетей поддержку адаптивных inline/sticky, interstitial
и rewarded. Фактическая интеграция, настройки placements и показ каждого
используемого формата проверяются на этапах 6–6 на обеих платформах.

Перед установкой в этапе 6 повторно сверить публикации. Если появится RN
8.6.x с подтверждённой поддержкой обоих SDK, рассматривать только новый
согласованный набор целиком и обновить эту матрицу. На этапе 0 проверена
совместимость метаданных выбранного набора; сборки, Gradle dependency
resolution, CocoaPods install и реальные рекламные запросы не выполнялись.
