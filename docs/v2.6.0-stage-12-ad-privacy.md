# Этап 12: согласия на персонализацию и рекламную геолокацию

09.11.2026. Реализовано перед финальным Gate (теперь этап 14, после добавления
проверки обновлений этапа 13). Пользователь подтвердил ожидаемое поведение
на Android; физическая iOS-приёмка и правовые декларации остаются открытыми.
Последняя успешная Cloud-сборка уже направлена пользователем на внутреннее
и внешнее тестирование; внешнее beta review ожидается, релиз не отправлялся.
Текущие правки потребуют новой сборки и повторной проверки затронутых сценариев.

## Интерфейс

`AdPrivacyModal` заменяет Alert: почти полноэкранное окно с собственной safe area,
скроллируемым содержимым и закреплёнными кнопками. Текст описывает рекламное
финансирование, поддержку разработчика, добровольность выбора и его отзыв,
состав данных, Yandex Mobile Ads и сети BIGO Ads / VK Реклама / Chartboost.
Политика конфиденциальности открывается по заданному URL с `lang=ru`.

Подтверждение совершеннолетия исходно пустое. Без него нельзя согласиться
или включить передачу геолокации; снятие галочки сбрасывает переключатель.
«Отказаться» доступна всегда. Правая кнопка согласия больше, использует accent
и анимированный блик; анимация выключается при Reduce Motion и в фоне.

Из «Прочее → Настройки» окно открывается с сохранёнными состояниями. Блок
показывает два независимых статуса с цветами `accent`/`error` и стрелкой.
Переключатель отражает **согласие на передачу**, а не текущее разрешение ОС:
согласие может быть включено при системном отказе для последующего разрешения.
Крестик/Back при редактировании закрывает окно без изменения настроек.
Back при первом показе равнозначен отказу. Сохранение происходит только
по «Согласиться» или «Отказаться»; отказ выключает оба согласия.

Внизу «Прочее», рядом с существующими ссылками, добавлены Политика
конфиденциальности (`shield-lock-outline`) и Условия использования
(`file-document-outline`) из MaterialCommunityIcons.

## Данные и жизненный цикл

`AdPrivacyPreferences` хранит локальный JSON `adPrivacyPreferences`:
версию объяснения, подтверждение совершеннолетия, персонализацию и геолокацию.
Несогласованные сочетания нормализуются в сторону запрета; повреждённая запись
или неизвестная версия требуют нового выбора. Старое `adUserConsent`
GRANTED/DENIED не переносится: в нём нет новых отдельных подтверждений.
После нового выбора старый ключ удаляется.

| Выбор | SDK `setUserConsent` | SDK `setLocationConsent` | Поля запросов MpeiApp |
| --- | --- | --- | --- |
| До первого выбора | false; SDK не инициализируется | false | Рекламные запросы заблокированы |
| Отказ | false | false | Без возраста, пола и координат |
| Согласие без геолокации | true | false | Приблизительный возраст и предполагаемый пол |
| Согласие с геолокацией | true | true | Возраст/пол; координаты только при системном доступе |

Возраст по-прежнему вычисляется по году поступления (резервное значение 19),
предполагаемый пол — локально по имени. Эти эвристики явно описаны в окне;
имя и группа, учётные данные, оценки и учебные сведения в запросы не включаются.
Если совершеннолетие не подтверждено, `setAgeRestrictedUser(true)` сообщает SDK
об ограничении обработки данных при неизвестном возрасте. Подтверждение возраста
само по себе не включает персонализацию.

`AdTargeting` по умолчанию не добавляет личные поля. Для координат требуются
оба рекламных согласия. Случайная подстановка точки МЭИ больше не используется
в запросах: без геолокации поле `location` отсутствует. Самостоятельный модуль
fallback и его прежние тесты сохранены как неиспользуемая совместимая утилита.

При включении геолокации запрашивается только foreground permission: iOS
`whenInUse`; Android проверяет имеющиеся права и при необходимости запрашивает
coarse/fine вместе, принимая approximate location. Отказ/ошибка не включают
рекламу до подтверждения формы и не мешают согласиться без системного доступа.
Доступ к карте не выдаёт согласия на рекламную геолокацию.

SDK privacy flags устанавливаются до инициализации и обновляются при каждом
сохранении. Открытое окно приостанавливает рекламные запросы. При изменении
согласий сбрасываются rewarded/preloads, native-баннеры получают новый жизненный
цикл. Старые callbacks создания запросов блокируются на время изменения.
Координаты карты принимаются только при обоих согласиях, не пишутся на диск
и очищаются при сохранении, смене аккаунта и уходе приложения в фон.
Системное разрешение требуется рекламному SDK дополнительно к app consent.
iOS location usage descriptions описывают карту и необязательную рекламную цель.

Технические сведения (IP, параметры устройства/ОС, показы/клики и доступные
по правилам ОС идентификаторы) обрабатываются самими рекламными SDK.
Отказ от персонализации не означает отсутствие сетевых обращений или IP.

## Проверки и ручная приёмка

Автоматические сценарии находятся в `__tests__/AdPrivacy-test.tsx`:
пустой/legacy выбор, отказ, adult gate, независимая геолокация, выдача/отказ
разрешения, применение только при сохранении, отзыв, повторное открытие,
сброс preloads, отсутствие координат, повреждённое хранилище и ссылка политики.
09.11 успешны `yarn typecheck` и `yarn test:ci`: **44 suites / 474 tests**,
включая **13 новых тестов** согласий. Отдельно проверены наличие всех выбранных
иконок в установленных glyphmaps и разбор iOS Info.plist. Проверены iOS
when-in-use/restricted и защита от возврата старых координат через сохранённый
callback. Нативная сборка и визуальная приёмка агентом не выполнялись;
позже пользователь подтвердил ожидаемое поведение на Android.

До Gate вручную проверить на Android и физическом iPhone:

| Сценарий | Ожидаемый результат |
| --- | --- |
| Чистая установка и обновление со старым согласием | Новое окно; оба переключателя исходно выключены; рекламы до выбора нет |
| Отказ без adult checkbox | Окно закрывается, оба статуса выключены; приложение доступно |
| Только персонализация | Возраст/пол разрешены, запрос местоположения не появляется |
| Геолокация: precise / approximate / denied | Системный запрос при включении; выбор пользователя сохраняется; отказ ОС не обходится |
| Доступ к карте при отказе рекламной геолокации | Карта работает; координаты не добавляются в рекламные запросы |
| Отзыв и повторное включение из настроек | Статусы меняются; SDK flags обновляются; старые баннеры/preloads не используются |
| Отзыв location permission в настройках ОС | После возврата старые координаты отсутствуют, SDK соблюдает системный запрет |
| Маленький экран, крупный шрифт, обе темы | Текст прокручивается, кнопки доступны, статусы читаемы |
| Reduce Motion, уход в фон | Анимация согласия останавливается |
| Ссылки на документы | Открываются заданные страницы на русском языке |
| Реальные сети медиации | Проверить privacy flags и реальный трафик до/после отказа и отзыва |

Отдельная правовая приёмка остаётся открытой: опубликованные документы должны
соответствовать реальным сетям, составу обработки и регионам распространения;
App Privacy / Data Safety и возрастные декларации — фактическому поведению.
Технические тесты приложения не доказывают полноту правового соответствия.
В текущем проекте нет собственного ATT-запроса, `NSPrivacyTracking` равен false.
Если рекламные интеграции выполняют tracking в смысле Apple, до релиза нужны
соответствующие ATT-разрешение и декларации; это окно не заменяет ATT и не
переопределяет системный отказ. Проверка поведения каждой native-сети остаётся
частью приёмки на устройстве.
