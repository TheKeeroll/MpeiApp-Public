# Этап 6: медиация Yandex Mobile Ads на Android и iOS

**Завершён в релизе 2.6.0 от 11.11.2026.** Android debug/release приняты
пользователем, iOS прошёл Simulator, Xcode Cloud и внешнее тестирование.
[Итоги релиза](v2.6.0-release.md). Это исторический отчёт;
[текущая конфигурация медиации](ads-mediation.md) описана отдельно.

RN-плагин и native Yandex SDK закреплены на 8.5.0 вместе с совместимыми
адаптерами BIGO Ads, VK Реклама и Chartboost. Mintegral/Liftoff в выпуск не вошли.
Выбор зафиксирован metadata и lockfiles, а не предположением о «самой новой» версии.

## Что изменено в репозитории

- `package.json` и `yarn.lock`: RN-плагин обновлён с 8.3.0 до 8.5.0.
- `android/app/build.gradle`: три отдельных адаптера и строгая версия
  Yandex SDK 8.5.0, ExoPlayer Core 2.18.7 для Chartboost и исключение
  неиспользуемого ServiceLoader descriptor Tracer Lite из myTarget.
  Общий пакет всех сетей не используется.
- `android/build.gradle`: репозиторий Chartboost подключён для app dependencies.
  Его content filter разрешает `com.chartboost` и модуль
  `com.iab.omid.library:chartboost-omsdk-android`; последний также отсутствует
  в Maven Central. Подключение только `com.chartboost` оставляло бы OM SDK
  неразрешённым. BIGO и VK доступны через Maven Central.
- `ios/Podfile`: три адаптера добавлены только в `MpeiApp`; autolinking
  продолжает подключать RN-плагин и его YandexMobileAds. ScheduleWidget
  рекламные pods не получает.
- `ios/MpeiApp/Info.plist`: добавлены 22 отсутствовавших SKAdNetwork ID,
  итог — 244 уникальных записи. Сохранены существующие ATS-настройки.
- `patches/yandex-mobile-ads+8.5.0.patch`: сохранены преобразование координат
  без несовместимого с RN 0.87 `RCTConvert.clLocationDegrees` и Android-защита
  загрузки/событий баннера при Fabric mount/unmount. Новая upstream-обработка
  `onInterceptTouchEvent` с `NativeGestureUtil` также сохранена.

Источники SKAdNetwork: [список Яндекса](https://ads.yandex.com/helpcenter/ru/dev/ios/skadnetwork)
и [JSON Chartboost](https://a3.chartboost.com/skadnetworkids.json), на который
ссылается [его iOS-инструкция](https://docs.chartboost.com/en/monetization/integrate/ios/get-started/).
Идентификатор Chartboost `f38h382jlk.skadnetwork` уже присутствовал.
У основного iOS target в Debug/Release уже есть `-ObjC` и `$(inherited)`.
Deployment target приложения 15.6 удовлетворяет podspec выбранных адаптеров
и YandexMobileAds, требующим iOS 15.0.

В опубликованном [ChartboostSDK 9.13.0](https://cdn.cocoapods.org/Specs/5/3/e/ChartboostSDK/9.13.0/ChartboostSDK.podspec.json)
дополнительно проверены device arm64 и simulator arm64/x86_64 slices,
их PrivacyInfo.xcprivacy и Info.plist. Framework собран Xcode 26.0
(`DTXcode=2600`, SDK iphoneos/iphonesimulator 26.0), minimum OS — 11.0.
Структура пакета проверена; приложение затем успешно собрано в Simulator и Cloud.

`AdsProvider` остаётся единственной точкой инициализации: сохранённые
`setUserConsent`/`setLocationConsent`/`setAgeRestrictedUser` передаются до `MobileAds.initialize()`.
Автоматическая инициализация Yandex на Android по-прежнему выключена манифестом.
Отдельных вызовов инициализации BIGO/VK/Chartboost из JS/AppDelegate не добавлено:
ими управляет медиация Яндекса. Прежние ad unit IDs и gates показа сохранены.

## Настройка рекламных кабинетов

Эти действия выполняет владелец аккаунтов. Код не создаёт приложения и placements
в рекламных сетях и не меняет настройки РСЯ. Для каждого сервиса создайте
отдельные приложения Android (`com.mpeiapp`) и iOS (`ru.NoobDragons.MpeiApp`).

| Сеть | Что подготовить в кабинете сети | Что связать в РСЯ |
| --- | --- | --- |
| BIGO Ads | App ID и Slot ID для используемых форматов | Добавить источник BIGO, указать запрошенные интерфейсом параметры приложения/слота |
| VK Реклама | Приложение и Slot ID для баннеров и rewarded | Добавить VK/myTarget с соответствующим Slot ID |
| Chartboost | App ID, App Signature и placements/locations для используемых форматов | Добавить Chartboost, указать credentials и placement соответствующего формата |

В [настройке медиации Яндекса](https://ads.yandex.com/helpcenter/ru/dev/react-native/quick-start-mm)
подключите источники к существующим блокам нужной платформы: отдельно для
inline/sticky и rewarded. Для указанных сетей Яндекс заявляет поддержку этих
форматов; interstitial в MpeiApp этим этапом не добавляется.
Наличие нужного формата в вашем аккаунте и допуск приложения к показам
проверяются в кабинете каждой сети.

Если интерфейс запрашивает ключи отчётности или bidding, используйте значения
своего аккаунта. Они сохраняются в рекламных кабинетах. IDs сетей не подменяют
Yandex ad unit IDs в JS: MpeiApp продолжает отправлять запросы через Yandex SDK.
Секреты кабинетов в Git не добавляются.

## iOS: воспроизводимая установка

Настоящий Podfile.lock получен resolver на Mac. В нём YandexMobileAds 8.5.0,
BIGO adapter 5.0.6.5 / BigoADS 5.0.6, myTarget adapter 5.36.2.5 /
myTargetSDK 5.36.2 и Chartboost adapter 9.13.0.1 / SDK 9.13.0.
Установка выполняется через frozen Bundler и `pod install --deployment`;
CocoaPods 1.17.0 / xcodeproj 1.28.1. Полный pod update для обычной сборки не нужен.

Команды и closed config: [Cloud README](../ios/ci_scripts/README.md).
Открывается ios/MpeiApp.xcworkspace, scheme MpeiApp; минимум app 15.6,
widget 17.0. Рекламные pods относятся только к основному приложению.

## Android: воспроизводимые проверки после изменения

Из каталога `android` (в Windows используйте `gradlew.bat`):

```bash
./gradlew :app:dependencies --configuration debugRuntimeClasspath --no-daemon
./gradlew :app:dependencies --configuration releaseRuntimeClasspath --no-daemon
```

Проверяйте строки `FAILED`, даже если команда закончилась `BUILD SUCCESSFUL`.
Ожидаются Yandex 8.5.0, три адаптера, Chartboost SDK 9.14.0, его OM SDK 1.6.7
и ExoPlayer Core 2.18.7 с транзитивными модулями той же версии.
В Windows оба дерева разрешены без `FAILED`. В опубликованном AAR Yandex 8.5.0
проверены consumer ProGuard rules для семейств mediation adapters;
дополнительный blanket keep в приложение не добавлялся.

### Состав release R8

Владелец проекта подтвердил успешную debug-сборку и запуск на эмуляторе.
При release-сборке R8 обнаружил отсутствующие `com.google.android.exoplayer2.*`,
а также предупредил о ServiceLoader descriptor Tracer Lite. Причины и правки:

- [Адаптер Chartboost 9.14.0.0](https://repo.maven.apache.org/maven2/com/yandex/ads/mediation/mobileads-chartboost/9.14.0.0/mobileads-chartboost-9.14.0.0.pom)
  исключает все транзитивные `com.google.android.exoplayer`, хотя SDK 9.14.0
  содержит реализации как Media3, так и старого ExoPlayer. Его consumer rules
  сохраняют весь `com.chartboost.sdk.**`, включая ссылки на старый проигрыватель.
  В приложение явно добавлен `com.google.android.exoplayer:exoplayer-core:2.18.7` —
  версия из [POM самого SDK](https://cboost.jfrog.io/artifactory/chartboost-ads/com/chartboost/chartboost-sdk/9.14.0/chartboost-sdk-9.14.0.pom).
  Core подтягивает common/datasource/database/decoder/extractor этой же версии.
  Media3 имеет другие имена классов и не заменяет отсутствующие типы.
  Такой состав проигрывателей также описан в [инструкции Chartboost](https://docs.chartboost.com/en/monetization/integrate/android/get-started/#exoplayer-dependency-for-video-ads).
- В `mytarget-sdk:5.51.2` присутствует
  `META-INF/services/ru.ok.tracer.manifest.TracerLiteManifest`, указывающий на
  `com.my.target.fj`, но самого интерфейса Tracer Lite в зависимостях нет.
  Этот единственный неиспользуемый descriptor исключён через
  `packagingOptions.resources.excludes`; остальные ServiceLoader entries сохранены.

Для ExoPlayer подключлены настоящие классы: подавление missing-class ошибок
через `-dontwarn` не добавлялось, минификация release остаётся включённой.
После правки `releaseRuntimeClasspath` разрешён без `FAILED`; в его артефактах
найдены все 34 класса из `missing_rules.txt` и остальные типы старого ExoPlayer,
на которые ссылается Chartboost (всего 41 тип). Дубликатов классов ExoPlayer нет.
Проверка Gradle DSL подтвердила адресное исключение Tracer descriptor;
остальные три ServiceLoader entries из release-зависимостей сохранены.
Владелец проекта подтвердил успешную release-сборку и работу APK после этих правок.

При изменении зависимостей проверяются merged manifest, дубли классов,
ABI, размер APK и R8. Существующие четыре jobs CI сохранены.

## Подтверждения

Пользователь подтвердил Android debug/release и работу APK; на Mac — установку
Pods, сборку/запуск Simulator, рекламу и карту. Последующая новая Cloud-сборка,
внешний TestFlight и общая iOS-приёмка завершены до публикации 11.11.2026.
JS/Swift/Kotlin patches и metadata проверены при реализации; итоговый общий
Jest-прогон записан в отчёте релиза.

Показ Yandex-баннера подтверждает его поток, но не является отдельным доказательством
показа каждой сети во всех форматах. Для диагностики конкретного провайдера
используются его placement, настройки кабинета и SDK/debug logs.
