# Этап 8: iOS-виджет расписания

**Завершён в релизе 2.6.0 от 11.11.2026.** Тестировщица подтвердила корректную работу виджета в новой TestFlight-сборке; iOS-приёмка закрыта.
[Итоги и приёмка релиза](v2.6.0-release.md).

## Выявленные причины

В коде были дефекты, не зависящие от конкретной версии iOS:

- При отсутствии `widgetKeyDay` ни одна ветка со списком занятий не выполнялась.
- `placeholder`/`snapshot` содержали строки `Placeholder`/`Data goes here`
  вместо JSON. При выбранном дне обработка отсутствующих данных доходила
  до `filteredLessons!`; неполные занятия также разыменовывались через `!`.
- Первая timeline entry датировалась будущим временем, на пять минут позже запроса.
- Общие данные записывались только из экрана оценок. Вызова WidgetCenter
  после записи не было, поэтому widget мог продолжать показывать старую timeline.
- Предупреждение было объявлено как `@Parameter String`: система показывала
  настоящее поле ввода с клавиатурой вместо информационного текста.

## Изменения

`useIOSScheduleWidgetSync` работает в корне приложения, независимо от выбранного
раздела. Собственный `ScheduleWidgetBridge` проверяет доступность App Group,
сохраняет JSON и вызывает `WidgetCenter.reloadTimelines(ofKind:)`.
При возврате приложения в foreground запрос повторяется. Это соответствует
[механизму обновления данных WidgetKit](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date).

Передаются только поля расписания, нужные виджету. Записи идут последовательно:
завершение старого запроса не может восстановить чужое расписание после logout.
Неудачное обновление без новых данных не стирает опубликованный кэш; начальная
подготовка приложения также сохраняет его до восстановления аккаунта.

С 08.11 App Group — **`group.org.mpeiapp`**, Bundle ID extension —
**`ru.NoobDragons.MpeiApp.ScheduleWidgets`**: старые имена остались у прежнего
Apple Account. Native bridge, provider и AppIntents используют один обновлённый
`ScheduleWidgetContract`. Ключи `widgetKey`/`widgetKeyDay` и kind
`ScheduleWidget` сохранены; общий кэш заново публикуется приложением в новую
группу, без чтения недоступного старого контейнера. Общая Foundation-модель
по-прежнему читает старый трёхдневный формат из 2.5.0 и
новый payload. Пропущенный/неизвестный выбор означает «Сегодня»; старые
`yesterday`/`tomorrow` при чтении мигрируют в конкретную допустимую дату.
Lunch/placeholder не отображаются; альтернативы одного временного слота
считаются одной парой.

### Две недели и переключение дней

Приложение передаёт ровно 14 дат: с понедельника текущей недели по воскресенье
следующей. Например, 20 октября 2026 года диапазон — 19.10–01.11. Даты и
«сегодня» определяются по Москве, как в ScheduleScreen, независимо от часового
пояса устройства. Содержимое берётся из уже загруженного студенческого
расписания Redux; дополнительных запросов и изменений Android-виджета нет.

Для каждой даты передаётся `isLoaded`. Существующий день с пустым `lessons`
означает «Занятий нет», отсутствующий/неполный день кэша — «На этот день
расписание не загружено». Старые payload без этого поля продолжают читаться.
При новом понедельнике открытое приложение пересобирает диапазон по таймеру;
возврат из background также обновляет его.

В виджете показана одна неделя — семь карточек. Стрелки рядом с диапазоном
дат переключают текущую/следующую неделю, сохраняя день недели; выбор карточки
показывает занятия этой даты. На границах диапазона соответствующая стрелка
неактивна. Это перелистывание кнопками, а не жестом: используется поддерживаемая
WidgetKit интерактивность через `Button(intent:)` без запуска приложения.
[Интерактивность виджетов у Apple](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities).

У карточек, как в приложении, есть день недели, число в круге и месяц.
Сегодняшняя дата сохраняет отдельную подсветку; выбранная карточка имеет
свой фон/рамку, поэтому выбор другого дня не скрывает сегодняшнюю дату.
Кнопка «Сегодня» возвращает на неё с любой страницы. Размер круга ограничен
шириной карточки, шрифты и цвета адаптируются к контексту виджета; VoiceOver
озвучивает дату, признак сегодняшнего дня, число пар/отсутствие данных и выбор.

Выбор хранится в прежнем `widgetKeyDay`: `today` следует за календарём,
конкретная дата сохраняется, пока входит в текущие две недели. Когда дата
выходит из диапазона, показывается сегодня. Переключение использует новый
`SelectScheduleDayIntent`; три прежних intent-имени сохранены для ранее
архивированных timeline.

Provider возвращает текущую entry сразу и дополнительные entries на ближайшие
14 московских полуночей, меняя подсветку и календарный диапазон даже при
закрытом приложении. Если новая неделя частично выходит за пределы сохранённых
данных, виджет просит загрузить расписание в приложении, не изображая пустой
учебный день. Gallery/placeholder получают валидный пример на две недели,
реальный пустой или повреждённый кэш — понятное сообщение. Полный JSON
расписания в native-логи больше не печатается.

Виджет использует StaticConfiguration без редактируемых параметров. Текст
«Откройте MpeiApp, чтобы загрузить или обновить расписание в виджете» виден
в описании и обычном блоке внутри виджета. Кнопки используют `.plain`, цвета
— `.primary`/`.secondary`, фон — системный. Число видимых строк зависит от
размера и шрифта; при нехватке места показано число оставшихся занятий.

Native bridge и модель добавлены в Sources проекта. Только deployment target
extension приведён к iOS 17 — уже используемому минимуму интерактивных
AppIntent-кнопок. Минимум основного приложения остался 15.6. Общая TS-сериализация используется также [Android-виджетом](v2.6.0-stage-9-android-widget.md)
без изменения контракта iOS.

У приложения и extension указан reason `1C8F.1` для UserDefaults внутри App
Group; manifest extension включён в Resources.
[Описание reason у Apple](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype).

## Проверки

Успешны 13 XCTest Foundation-модели: старый/повреждённый JSON, неполные занятия,
двухнедельный диапазон, выбор дат и «Сегодня», полночь/понедельник, граница года,
високосный день и DST. Повторный запуск на Mac:

```bash
swift test --package-path ios/ScheduleWidgetCore
```

Jest проверяет сериализацию, отсутствие мутации Redux, незагруженный и пустой день,
очередь/retry native-записи, logout, offline, foreground и смену недели.
Simulator build/preview проверены на Mac; итоговая Cloud-сборка и работа
размещённого виджета подтверждены через внешнее тестирование до релиза.

## Регрессионные сценарии на Mac и устройстве

1. Завершить CocoaPods/медиацию по этапу 7, открыть `ios/MpeiApp.xcworkspace`.
   Проверить Sources у MpeiApp (bridge Swift/Obj-C и общая модель) и
   ScheduleWidgetExtension (модель, provider/view и AppIntent), а также Resources
   с `PrivacyInfo.xcprivacy`. Членство файлов уже записано в проект.
2. В Signing & Capabilities обоих targets проверить доступ к
   `group.org.mpeiapp`, включая Release provisioning. Entitlements и runtime-контейнер совпадают;
   новое имя группы создавать не нужно.
3. Проверить gallery/preview `.systemLarge`: расписание-пример отображается,
   предупреждение — обычный текст, поля ввода и клавиатуры нет.
4. Проверить чистую установку: виджет до первого входа показывает пояснение.
   Открыть приложение и дождаться загрузки расписания, не заходя в оценки:
   виджет должен получить данные. Повторить с offline-кэшем.
5. Установить обновление поверх 2.5.0 с уже добавленным виджетом. Релиз
   использует `group.org.mpeiapp`: после открытия приложения данные должны
   попасть в этот контейнер. Проверить чтение старого JSON и default «Сегодня» при отсутствующем
   ключе выбора; отдельно проверить миграцию выбранных вчера/завтра.
   После открытия приложения проверить диапазон из 14 дат и выбор каждого дня,
   стрелки в обе стороны, сохранение дня недели и возврат кнопкой «Сегодня».
6. Проверить день без занятий, отсутствующий день, длинные названия и крупный
   шрифт. Проверить светлый, тёмный, tinted и clear/glass режимы iOS 26.x,
   а также iOS 17/18 и VoiceOver. При выборе другого дня сегодняшний остаётся
   выделен. Проверить полночь и новый понедельник без открытия app: новый
   диапазон, сброс устаревшего выбора и честное сообщение для незагруженных дат.
   После возврата в приложение данные следующей недели должны обновиться.
7. Проверить logout и смену аккаунта: старые данные не возвращаются после
   завершения отложенной записи; новые данные заменяют их после загрузки.
8. В Console при проблеме проверить сообщения `iOS schedule widget` и crash
   logs процесса ScheduleWidgetExtension. Ошибка App Group требует проверки
   capabilities/provisioning; она не означает отсутствие расписания на сервере.
